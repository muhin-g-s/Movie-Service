# Гейты качества харнеса

> **Отвечает за:** перечень гейтов качества харнеса и сервиса, где они срабатывают, чем реализованы и чем обходятся, а также пример запуска проверок в CI.
> **Не содержит:** списка проверок `docs-lint` и команд ([reference.md](reference.md)), критериев ревью кода ([code-review.md](../../code-review.md)) и самих принципов ([конституция](../../.specify/memory/constitution.md)).
> **Читать когда:** нужно понять, что остановит поломку, что ее пропустит и как перенести проверки в CI.
> **Проверено при версии конституции:** 3.0.0

**TL;DR:** сейчас гейты работают в сессии Claude Code и перед коммитом на машине владельца. Остальное запускается вручную. CI нет, поэтому согласованность `main` держится на хуках и дисциплине. Пример CI в конце документа ничем не подключен.

## Гейты по моменту срабатывания

### Во время сессии

| Гейт | Чем реализован | Что делает | Чем обходится |
|---|---|---|---|
| запрет секретов и опасных команд | правила разрешений в `.claude/settings.json` | блокирует чтение `.env` инструментом Read, force push и коммит с `--no-verify` | чтение через Bash, команды человека |
| подтверждение правки конституции | правило разрешений и `tools/guard-constitution.py` | просит подтверждение пользователя | команды вне эвристики, последняя защита проверка версии при коммите |
| проверка после правки файла | хук PostToolUse и `tools/docs-lint.py` с флагом `--hook` | сообщает агенту о нарушениях в правленом файле | не блокирует, только сообщает |
| проверка при старте сессии | хук SessionStart и `tools/docs-lint.py` с флагом `--session` | показывает нарушения, включает git-хук | не блокирует |
| напоминание о записи решений | хук Stop и `tools/capture-reminder.py` | периодически просит агента найти незаписанные решения, частота описана в [справочнике](reference.md#скрипты) | зависит от добросовестности модели |

### Перед коммитом

| Гейт | Чем реализован | Что делает | Чем обходится |
|---|---|---|---|
| проверка при коммите | `.githooks/pre-commit` и `tools/docs-lint.py` с флагом `--staged` | блокирует коммит при любом нарушении, дополнительно проверяет рост версии конституции и отсутствие временного отчета | коммит с `--no-verify` у человека, клон без настроенного хука |

### По запросу

| Гейт | Чем реализован | Что делает | Надежность |
|---|---|---|---|
| тесты харнеса | `tests/harness/` | проверяют скрипты, хуки, git-хук, `docs-lint`, покрытие и состав харнеса | детерминированно, быстро |
| сценарии поведения | `tools/harness-eval.py` и `evals/cases/` | проверяют, что агент следует правилам на рабочей и слабой моделях | статистически, стоят токенов |
| проверка с чистого листа | скилл `cold-start` | показывает, находит ли новый агент факты только по репозиторию | статистически |
| смысловой аудит | скилл `audit` | ищет противоречия между конституцией и файлами харнеса | вероятностно, нужна проверка человеком |
| проверка артефактов фичи | `/speckit-analyze` и `/speckit-checklist` | находит несогласованность спецификации, плана и задач до реализации | вероятностно |
| проверка плана по конституции | Constitution Check в шаблоне плана | нарушения устраняются или обосновываются в разделе Complexity Tracking | зависит от агента |
| дрейф шаблонов Spec Kit | `tools/docs-lint.py` с патчами и манифест тестов | замечает расхождение шаблонов после обновления Spec Kit | детерминированно |

### Для кода сервиса

Гейты кода появятся вместе с кодом и сейчас не реализованы, тема записана в [реестре отложенных решений](../decisions/README.md#отложенные-решения). Правила уже заданы:

- тесты пишутся первыми и падают по правильной причине, принцип VI конституции
- контрактные и интеграционные тесты, принципы III и VI
- критерии ревью и приоритеты замечаний из [code-review.md](../../code-review.md), замечания P0 и P1 блокируют принятие

## Что гейты не ловят

- смысловые противоречия между файлами, их ищет только `audit`, а он вероятностный
- нарушения, внесенные в коммит с `--no-verify`
- нарушения в клоне, где не включен git-хук, вне сессий Claude Code
- сбой хука Spec Kit после `/speckit-implement`, это проверит первая фича
- нарушения правил слабой моделью, их показывают сценарии поведения, но не предотвращают

## Пример запуска в CI

Это пример. В репозитории CI не настроен, платформа, образ и окружение не выбраны, тема записана в [реестре отложенных решений](../decisions/README.md#отложенные-решения). Пример показывает, какие гейты переносятся и как.

Что переносится в CI без изменений:

- `python3 tools/docs-lint.py` без флагов
- `python3 -m unittest discover -s tests/harness`

Что требует доработки:

- проверка роста версии конституции работает по индексу git и в CI не подходит, нужна замена сравнением с целевой веткой, этого сейчас нет
- сценарии поведения нужны установленный `claude` и ключ доступа, их разумно запускать по расписанию или вручную, а не на каждый коммит

Что в CI не переносится: подтверждение правки конституции, проверки в сессии и напоминания, они работают только в сессии Claude Code.

```yaml
# Пример для GitLab CI. Не подключен к репозиторию.
stages:
  - harness-fast
  - harness-behavior

default:
  image: python:3.12   # пример: нужны git, diff и patch, версия образа примерная

harness:docs-lint:
  stage: harness-fast
  script:
    - python3 tools/docs-lint.py

harness:tests:
  stage: harness-fast
  script:
    - python3 -m unittest discover -s tests/harness

harness:behavior:
  stage: harness-behavior
  image: node:22   # нужны Node для claude, а также python3, git, diff и patch
  rules:
    - if: $CI_PIPELINE_SOURCE == "schedule"
    - when: manual
      allow_failure: true
  before_script:
    - npm install -g @anthropic-ai/claude-code   # ключ в защищенной переменной проекта
  script:
    - python3 tools/harness-eval.py --models sonnet,haiku --runs 3 --parallel 4
  artifacts:
    when: always
    paths:
      - evals/results/
    expire_in: 14 days
```

Замечания к примеру:

- Быстрые задачи нужно сделать обязательными для слияния ветки, поведенческую оставить по расписанию.
- Код возврата поведенческой задачи определяет рабочая модель, провалы слабой модели только показываются в таблице.
- Стоимость полного прогона записана в [ADR 0006](../decisions/0006-harness-test-layers.md), предохранитель на запуск задается флагом `--budget`.
