# Пул возможностей харнеса

> **Отвечает за:** перечень того, что харнес умеет сейчас, с разделением по источникам: Spec Kit, OMC, обвязки проекта.
> **Не содержит:** команд и флагов ([reference.md](reference.md)), устройства и зависимостей ([infrastructure.md](infrastructure.md)), правил применения OMC ([CLAUDE.md](../../CLAUDE.md)) и разграничения процесса ([AGENTS.md](../../AGENTS.md#разграничение-процесса)).
> **Читать когда:** нужно понять, что уже есть, чему это обязано и чего пока нет.
> **Проверено при версии конституции:** 3.0.0

**TL;DR:** харнес ведет фичу от идеи до задач (Spec Kit), исполняет задачи по ролям (OMC) и держит правила, знания и документацию согласованными (обвязки проекта). Ниже три списка по источникам, сводная матрица и перечень того, чего пока нет.

## Благодаря Spec Kit

Spec Kit установлен интеграцией, его версия записана в `.specify/init-options.json`.

| Возможность | Чем обеспечена |
|---|---|
| поправка конституции по шаблону с отчетом о влиянии | скилл `speckit-constitution` |
| спецификация фичи из описания на естественном языке | скилл `speckit-specify` |
| до пяти уточняющих вопросов, ответы записываются в спецификацию | скилл `speckit-clarify` |
| план реализации с исследованием, моделью данных, контрактами и проверкой по конституции | скилл `speckit-plan`, шаблон плана |
| упорядоченный по зависимостям список задач | скилл `speckit-tasks`, шаблон задач |
| выполнение задач из списка | скилл `speckit-implement` |
| проверка согласованности спецификации, плана и задач без изменений | скилл `speckit-analyze` |
| чек-лист под конкретную фичу | скилл `speckit-checklist` |
| сверка кода со спецификацией, планом и задачами и дописывание недостающих задач | скилл `speckit-converge` |
| последовательная нумерация фич и создание каталога фичи | скрипты в `.specify/scripts/bash/` |
| хуки до и после каждой команды | файл `.specify/extensions.yml`, который читают скиллы |
| подмена шаблонов на уровне проекта | стек переопределений: проект, пресеты, расширения, ядро |

Поставляемый воркфлоу `.specify/workflows/speckit/workflow.yml` лежит в проекте, но харнес его не использует. Вместо него харнес использует свою цепочку `feature-chain`, она описана в [справочнике](reference.md#автоматизация-ai-среды).

## Благодаря OMC

OMC подключен на уровне пользователя, версия плагина указана в [infrastructure.md](infrastructure.md#внешние-зависимости). Перечень ниже составлен по окружению сессии на 15 ноября 2026 года и не заменяет справку плагина. Проект допускает только исполнительную роль OMC, это решение записано в [ADR 0001](../decisions/0001-spec-kit-and-omc-roles.md).

| Что | Состояние в проекте |
|---|---|
| исполнение шага задачи агентом по роли: исследование, тесты, реализация, проверка | используется, раскладка ролей в [CLAUDE.md](../../CLAUDE.md#omc) |
| автономные режимы `autopilot`, `ralph`, `ultrawork`, `team` | разрешены только на утвержденные задачи из списка задач и вне горячих зон |
| режимы планирования `plan`, `ralplan` | запрещены для работы по фиче, планирование ведет Spec Kit |
| инструменты LSP, ast-grep, исполнение Python | доступны, проектных правил нет |
| помощники анализа и отладки: `debug`, `trace`, `verify`, `ultraqa`, `deep-interview` | доступны, проектных правил нет |
| помощники оформления скиллов `skillify` и `learner` | `skillify` указан в CLAUDE.md для оформления скиллов проекта |
| память и заметки OMC, wiki, project memory | существуют, источником истины не являются |
| состояние в `.omc/` | эфемерно, игнорируется git |
| автоматические действия при старте сессии: подмешивание контекста проекта, уведомление об обновлении | работают сами, проект их не настраивает |

Полный перечень скиллов, агентов и инструментов OMC находится в справке самого плагина, этот документ его не повторяет.

## Сводная матрица

| Возможность | Spec Kit | OMC | Обвязки проекта |
|---|---|---|---|
| вести фичу от идеи до кода | команды цикла, шаблоны, нумерация | исполняет отдельные задачи | тесты первыми в шаблоне задач, версия конституции в плане, `docs-sync` после реализации |
| проверять артефакты фичи | `analyze`, `checklist`, `converge` | `verifier`, `code-reviewer` проверяют код | критерии в `code-review.md`, проверка версии в планах |
| держать принципы и защищать их | `speckit-constitution` | нет | конституция, запрос подтверждения, проверка версии, метки, хуки после поправки |
| исполнять задачи по ролям | нет | роли и параллельные режимы | правила применения, запрет автономных режимов на идею |
| не терять знания из чата | `clarify` пишет ответы в спецификацию | память OMC как кэш | `capture`, `harvest`, напоминания, таблица маршрутизации |
| держать документацию согласованной | нет | нет | карта, шапки, метки, `docs-lint`, `docs-sync`, `audit` |
| проверять самого себя | нет | нет | тесты, сценарии, `cold-start`, покрытие, манифест |
| изолировать зависимости | нет | единственный разрешенный плагин | настройки проекта, проверка настроек, предупреждение |
| переживать обновление Spec Kit | стек переопределений | нет | патчи и проверка дрейфа |
| хранить решения | нет | нет | реестр отложенных решений, ADR |

## Чего харнес пока не умеет

Все пункты записаны в [реестре отложенных решений](../decisions/README.md#отложенные-решения):

- запускать проверки и тесты в CI
- запускать тесты харнеса перед каждым коммитом
- проверять код сервиса: продуктовые гейты появятся вместе с кодом
- сверять код с документацией: карта влияния путей кода на документы
- опираться на настоящие данные всех хуков вместо восстановленных
- держать правила харнеса на слабых моделях
- изолировать пользовательские MCP-серверы, добавленные отдельно от плагинов
