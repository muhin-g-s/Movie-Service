# Харнес

> **Отвечает за:** границу между харнесом и продуктом, состав зон репозитория и навигацию по документации харнеса.
> **Не содержит:** возможностей ([capabilities.md](capabilities.md)), устройства и зависимостей ([infrastructure.md](infrastructure.md)), команд и справочника ([reference.md](reference.md)), гейтов ([quality-gates.md](quality-gates.md)), кирпичиков воркфлоу ([bricks.md](bricks.md)).
> **Читать когда:** работаете над харнесом или не уверены, к какой зоне относится файл.
> **Проверено при версии конституции:** 3.0.0

**TL;DR:** в репозитории два проекта: сервис совместного просмотра фильмов и харнес, то есть среда, которая делает работу ИИ-агентов над сервисом надежной. У харнеса свои файлы, тесты и проверки, граница между зонами описана ниже.

## Что такое харнес

Харнес складывается из трех источников:

- **Spec Kit** ведет жизненный цикл фичи: спецификация, план, задачи, реализация.
- **OMC** исполняет утвержденные задачи агентами по ролям.
- **Обвязки проекта** держат правила, документацию и знания согласованными: инструкции, скрипты, хуки, скиллы, тесты.

Кто что умеет, перечислено в [capabilities.md](capabilities.md). Решение о разграничении Spec Kit и OMC записано в [ADR 0001](../decisions/0001-spec-kit-and-omc-roles.md), решение о двух зонах в [ADR 0003](../decisions/0003-harness-and-product-zones.md).

| `.githooks/` | харнес | git-хук проверки перед коммитом |
| `tools/` | харнес | скрипты проверок, хуков, анализа сессий и сценариев |

| `evals/` | харнес | сценарии поведения агента |

## Правила границы

1. Код сервиса не вызывает и не импортирует файлы харнеса. Харнес может читать продукт, например для проверок, продукт харнес не использует.
2. Знания о сервисе живут в зоне продукта. Файлы харнеса ссылаются на них и не копируют.
3. Изменение харнеса проверяют тесты харнеса и проверка документации, изменение сервиса проверяют тесты сервиса по принципу VI конституции.
4. Общие файлы обслуживают обе зоны. Правило в них относится к той зоне, которая названа в самом правиле.
5. Ограничения и долг харнеса описаны в этой папке и в [реестре отложенных решений](../decisions/README.md#отложенные-решения), а не в файлах продукта.
