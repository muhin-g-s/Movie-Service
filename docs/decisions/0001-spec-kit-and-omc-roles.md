# ADR 0001: Spec Kit ведет цикл фичи, OMC исполняет задачи

> **Отвечает за:** причины и альтернативы решения: разграничение Spec Kit и OMC.
> **Не содержит:** текущих правил и команд, они в файлах-владельцах из раздела связанных файлов.
> **Читать когда:** хотите изменить роли инструментов или понять, почему они разведены.
> **Проверено при версии конституции:** 3.0.0

**Статус:** принято, 2026-11-15.

## Контекст

Оба инструмента умеют планировать, вести списки задач и исполнять работу. Без разграничения возможны четыре пересечения:

- две точки входа в реализацию: команда `/speckit-implement` и исполнители OMC
- два списка задач: `tasks.md` и планы OMC
- два места исследований: `research.md` фичи и состояние в `.omc/`
- автономные режимы OMC идут от идеи к коду и обходят спецификацию, на которой стоит принцип I конституции

## Решение

Spec Kit ведет жизненный цикл фичи и владеет ее артефактами. Статус задач хранится только в `tasks.md`, исследования только в `research.md`. OMC исполняет утвержденные задачи по ролям. Автономные режимы допустимы только на утвержденные задачи, режимы планирования OMC для работы по фиче не используются, состояние `.omc/` эфемерно и источником истины не является.

## Рассмотренные варианты

- OMC ведет весь процесс, Spec Kit дает только шаблоны. Отвергнуто: планы OMC не дают утвержденной спецификации.
- Только Spec Kit, без OMC. Отвергнуто: нет ролей исполнения и параллельных режимов.
- Равные права обоих. Отвергнуто: дубли и два источника истины по статусу задач.

## Последствия

- Правила закреплены в инструкциях и проверяются сценариями поведения. На слабой модели они не держатся, это записано в реестре отложенных решений.
- Разграничение будет уточнено по результатам пилотной фичи.
- Хук Spec Kit для автоматической синхронизации документации после реализации пока не проверен на реальной фиче.
