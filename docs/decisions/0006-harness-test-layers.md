# ADR 0006: Слои тестов харнеса и схема на двух моделях

> **Отвечает за:** причины и альтернативы решения: способ проверять, что харнес работает так, как задумано.
> **Не содержит:** текущих правил и команд, они в файлах-владельцах из раздела связанных файлов.
> **Читать когда:** меняете тесты харнеса, сценарии поведения или предлагаете запускать их автоматически.
> **Проверено при версии конституции:** 2.4.1

**Статус:** принято, 2026-11-15.

## Контекст

Харнес состоит из кода и документов, а поведение агентов вероятностное. Нужно в любой момент понимать, что система работает как задумано и что правки ее не рассыпают.

## Решение

Четыре слоя. Первый: тесты скриптов с мутационными случаями на каждую проверку. Второй: тесты проводки хуков на эталонных данных, два события захвачены вживую, остальные восстановлены по документации, и тест git-хука. Третий: сценарии поведения, которые запускают Claude Code без интерфейса во временной копии репозитория. Четвертый: проверки дрейфа в живой работе, то есть проверка при старте сессии, метки актуальности и смысловой аудит. Обязательны правило покрытия, где у каждого файла харнеса есть запись о тестах, и эталонный манифест состава. Ошибка харнеса сначала становится тестом или сценарием. Сценарии идут на двух моделях: рабочая определяет код возврата, слабая показывает запас прочности. Основа проверок детерминированная, модель-судья не используется. Сценарии запускаются вручную.

## Рассмотренные варианты

- Только unit-тесты скриптов. Отвергнуто: не проверяют поведение агента.
- Только ручной аудит. Отвергнуто: не воспроизводим.
- Встроенный `claude plugin eval`. По справке Claude Code рассчитан на плагины, применимость к проектным скиллам не проверена, раннер написан по тому же формату случаев и проверок.
- Все сценарии только на слабой модели. Отвергнуто: ложные тревоги и пропуски.
- Тесты в git-хуке и CI. Отложено, записано в реестре отложенных решений.

## Последствия

- По первому прогону 15 ноября 2026 года рабочая модель проходит все быстрые сценарии, слабая нарушает принципы I и IX и теряет решения, поэтому слабые модели без усиления инструкций не поддерживаются.
- По замерам того же дня полный быстрый прогон стоит порядка четырех долларов, быстрые тесты идут около четырнадцати секунд.
- Результаты статистические, нужны повторные запуски и порог.
