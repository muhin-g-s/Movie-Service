# ADR 0009: Файловый трекер работы

> **Отвечает за:** причины и альтернативы решения: вести эпики и элементы работы файлами в каталоге `work/` с выводом статуса из артефактов Spec Kit.
> **Не содержит:** формата элементов и команд ([справочник харнеса](../harness/reference.md#трекер-работы)) и содержимого планов, оно принадлежит владельцу.
> **Читать когда:** предлагаете сменить способ планирования работы или подключить внешний трекер.
> **Проверено при версии конституции:** 3.0.0

**Статус:** принято, 2026-11-17.

## Контекст

Spec Kit ведет жизненный цикл одной фичи, но не знает эпика, очередности фич, зависимостей и прогресса по набору фич. Для крупных активностей вроде MVP нужен механизм, который живет в репозитории, не расходится со Spec Kit и не требует ручного поддержания статусов.

## Решение

Каталог `work/` в корне, не в `docs/`: один файл на элемент с плоской шапкой и свободным описанием. Элементы связаны вверх (`parent`, `depends`), у фичи есть поле `spec` со ссылкой на каталог Spec Kit. Статус фичи со `spec` и статус эпика выводятся из артефактов и не хранятся, ручной статус только у элементов без `spec`. Каждый каталог в `specs/` должен быть привязан к элементу, проверка блокирует коммит иначе. Инструмент `tools/work.py` детерминированный, диалоговые скиллы `epic-new`, `work-start` и `work` лежат поверх него. Передача в Spec Kit идет по одной фиче, из состояния "идея" в "готово к работе" элемент переводит только владелец. Данные трекера относятся к зоне продукта, инструмент и проверки к зоне харнеса.

## Рассмотренные варианты

- Файл `roadmap.md` в документации. Отвергнуто: статус пришлось бы вести руками, он разошелся бы со `tasks.md`.
- Расширение Epic из каталога сообщества Spec Kit. Не выбрано: расширения каталога только для обнаружения и требуют проверки, это новая внешняя зависимость по принципу IX, его код не проверялся.
- Внешний трекер (Jira и подобные). Отвергнуто: источник истины уходит из репозитория.
- JSON вместо Markdown с шапкой. Отвергнуто: Markdown читается людьми и агентами без инструментов, стандартной библиотеки Python хватает для разбора.

## Последствия

- Любая новая фича обязана пройти через трекер, иначе проверка при коммите не пройдет.
- Расхождение трекера и Spec Kit невозможно по построению, но связь `spec` ставится вручную скиллом `work-start`, ошибка видна проверкой.
- Содержимое эпика MVP трекер не содержит, его описывает владелец.
- Параллельность элементов определяется только зависимостями, места частых конфликтов правок пока решает владелец, см. [реестр отложенных решений](README.md#отложенные-решения).
