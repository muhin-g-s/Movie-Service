# ADR 0007: Движок воркфлоу Spec Kit для цепочек без диалога

> **Отвечает за:** причины и альтернативы решения: использовать ли встроенный движок воркфлоу Spec Kit для кирпичиков и контрольных точек.
> **Не содержит:** каталога кирпичиков ([bricks.md](../harness/bricks.md)), описания воркфлоу и команд ([справочник харнеса](../harness/reference.md)),.
> **Читать когда:** проектируете воркфлоу, гейты или автоматические цепочки шагов.
> **Проверено при версии конституции:** 3.0.0

**Статус:** принято, 2026-11-15.

## Контекст

Для сценариев работы нужны кирпичики (именованные шаги) с контрольными точками и уровнями контроля. Spec Kit 1.4.0 уже содержит движок воркфлоу: шаги `command`, `prompt`, `shell`, `gate`, `if`, `switch`, `while`, `do-while`, `fan-out`, `fan-in`, `slot` и вложенный воркфлоу, а также наложения (overlay), которые вставляют, заменяют или убирают шаги чужого воркфлоу из файла проекта. Воркфлоу `speckit` лежит в `.specify/workflows/speckit/workflow.yml`, до сих пор харнес его не использовал.

Опыт на копии репозитория показал: шаг `command` запускает неинтерактивный процесс Claude с полным контекстом проекта, хуки проекта в нем срабатывают, гейт без терминала ставит запуск на паузу с возможностью продолжить командой `specify workflow resume`. Но агент, остановившийся за подтверждением прав или с вопросом к пользователю, для движка выглядит как успех с кодом возврата 0, и запуск доходит до гейта над несуществующим результатом.

## Решение

Движок используется только для цепочек без диалога, которые идут после утвержденной спецификации: план, задачи, реализация, проверки. Шаги, где агент задает вопросы (`specify`, `clarify`), и интерактивная работа остаются в сессии. После каждого шага `command` в воркфлоу стоит шаг `shell` с детерминированной проверкой результата. Собственные шаги харнеса подключаются наложениями, а не правкой воркфлоу Spec Kit. Каталог кирпичиков остается файлом харнеса, воркфлоу движка проверяются по нему. Неинтерактивным шагам нужны правила разрешений на скрипты Spec Kit, иначе шаг останавливается на запросе прав. Папка состояния запусков игнорируется git.

## Рассмотренные варианты

- Собственный формат воркфлоу и свой исполнитель. Отвергнуто: движок уже решает паузы, продолжение, ветвление и параллельность, а наложения решают задачу дрейфа при обновлении Spec Kit.
- Перевести на движок всю работу. Отвергнуто: диалоговые шаги в нем невозможны.
- Не использовать воркфлоу вообще, оставить только скиллы. Отвергнуто: нет контрольных точек и воспроизводимых цепочек.

## Последствия

- Нужны правила `allow` для скриптов Spec Kit в настройках проекта, это поправка безопасности и она узкая.
- Каждый шаг `command` сопровождается проверкой `shell`, иначе возможен ложный успех.
- Шаг `command` движка всегда превращает имя в вызов `/speckit-...`, поэтому скиллы проекта вызываются шагом `prompt` с текстом `/имя-скилла`.
- Правила `allow` из настроек проекта неинтерактивный запуск применяет только в доверенной рабочей папке, то есть после того, как владелец принял доверие в интерактивной сессии. В копиях репозитория в других путях этого нет, шаг останавливается на запросе прав.
- Проверка цепочки на копии репозитория показала: переход по условию и остановка на гейте без терминала работают, упавшая проверка останавливает запуск. План на тестовой фиче остановился из-за отложенных решений о структуре кода, это штатное поведение по принципу IX. Шаги задач, реализации и синхронизации документов целиком не прогонялись.
- Расход токенов на цепочку не измерен.
- Хуки Stop и права внутри цепочки проверены не полностью, это нужно подтвердить на пилотной фиче.
