# Решения

> **Отвечает за:** архив архитектурных решений (ADR) и реестр отложенных решений.
> **Не содержит:** текущего устройства системы ([architecture](../architecture/README.md)) и принципов ([конституция](../../.specify/memory/constitution.md)).
> **Читать когда:** хотите узнать, почему сделано так, или проверяете, решена ли тема.

**TL;DR:** ADR пока нет, первые появятся после фиксации AI-платформы и до пилотной фичи. Реестр ниже перечисляет все, что мы осознанно не решили.

## ADR

Не определено. Формат и нумерацию выберем при создании первых ADR. Кандидаты: разграничение Spec Kit и OMC, причины выбора стека Backend.

Намерение, не правило. Конкретика появится с первым ADR:

- ADR фиксирует причины и отвергнутые альтернативы решения. Текущее устройство остается в [architecture](../architecture/README.md), ограничения в конституции.
- Архитектурное решение из `plan.md` или `research.md` фичи при необходимости переносится в ADR, чтобы пережить фичу.
- Поправка конституции будет ссылаться на ADR с обоснованием.
- Агент перед изменением архитектурного решения будет сверяться с ADR, для этого в [AGENTS.md](../../AGENTS.md) появится указатель.

## Отложенные решения

Здесь перечислено все, что осознанно не решено. Кроме стека Backend и архитектурных принципов из конституции, решений в проекте нет, пока тема не удалена из этой таблицы и не перенесена в файл-владелец. Агент не придумывает содержимое для этих тем (принцип IX).

| Тема | Что нужно решить | Где будет записано | Когда решаем |

| структура репозитория и кода | директории Backend, пакета контрактов, тестов | [architecture](../architecture/README.md), [README.md](../../README.md) | вместе с MVP |

Правила ведения реестра:

- Когда тема решена, строка удаляется, а решение записывается в файл-владелец.
