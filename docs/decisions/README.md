# Решения

> **Отвечает за:** архив архитектурных решений (ADR) и реестр отложенных решений.
> **Не содержит:** текущего устройства системы ([architecture](../architecture/README.md)) и принципов ([конституция](../../.specify/memory/constitution.md)).
> **Читать когда:** хотите узнать, почему сделано так, или проверяете, решена ли тема.

**TL;DR:** ADR пока нет, первый появится вместе с первым решением, которое нужно зафиксировать. Реестр ниже перечисляет все, что мы осознанно не решили.

## ADR

Не определено. Формат и нумерацию выберем, когда понадобится первый ADR.

Намерение, не правило. Конкретика появится с первым ADR:

- ADR фиксирует причины и отвергнутые альтернативы решения. Текущее устройство остается в [architecture](../architecture/README.md), ограничения в конституции.
- Архитектурное решение из `plan.md` или `research.md` фичи при необходимости переносится в ADR, чтобы пережить фичу.
- Поправка конституции будет ссылаться на ADR с обоснованием.
- Агент перед изменением архитектурного решения будет сверяться с ADR, для этого в [AGENTS.md](../../AGENTS.md) появится указатель.

## Отложенные решения

Здесь перечислено все, что осознанно не решено. Кроме стека Backend и архитектурных принципов из конституции, решений в проекте нет, пока тема не появилась в этой таблице как решенная и не перенесена в файл-владелец. Агент не придумывает содержимое для этих тем (принцип IX).
