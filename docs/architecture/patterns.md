# Каталог образцов

> **Отвечает за:** каталог утвержденных образцов реализации: когда применять, где лежит эталонный код, какие инварианты обязательны.
> **Не содержит:** самого кода (владелец способа реализации это эталонный код) и порядка работы по фиче ([AGENTS.md](../../AGENTS.md#выполнение-задачи)).
> **Читать когда:** составляете план фичи или реализуете то, что уже делалось в проекте.
> **Проверено при версии конституции:** 3.0.0

**TL;DR:** образцов пока нет, код сервиса не написан. Образцом становится только то, что утвердил владелец, агент образцы сам не объявляет. Каталог указывает на эталонный код и не копирует его. Структура кода и первый образец не определены, см. [реестр отложенных решений](../decisions/README.md#отложенные-решения).

## Как это работает

- В плане фичи обязательно поле Pattern: имя образца из таблицы ниже или `нет` с причиной.
- После реализации агент предлагает владельцу добавить новый образец или отметить отклонение. Запись попадает в таблицу только после подтверждения.
- Для образца с эталонным кодом проверка документации сверяет, что путь существует и указанный коммит есть в истории.
- Подсказка по статусам: `черновик` значит предложен агентом, `утвержден` значит подтвержден владельцем.
