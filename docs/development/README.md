# Разработка

> **Отвечает за:** руководство разработчика: проверка документации, автоматизация AI-среды, а позже окружение, команды, тестирование.
> **Не содержит:** принципов ([конституция](../../.specify/memory/constitution.md)) и инструкций агентам ([AGENTS.md](../../AGENTS.md)).
> **Читать когда:** настраиваете клон репозитория или ищете, как проверить и запустить.
> **Проверено при версии конституции:** 2.4.0

**TL;DR:** кода еще нет, поэтому сборка, окружение и тесты намеренно не определены, см. [реестр отложенных решений](../decisions/README.md#отложенные-решения). Описаны только проверка документации и автоматизация AI-среды.

## Первичная настройка клона

После клонирования выполните один раз:

```bash
git config core.hooksPath .githooks
```

Затем перезапустите Claude Code, чтобы применились настройки проекта. В сессиях Claude Code git-хук включается автоматически при старте, если он выключен.

## Проверка документации

Запуск, нужны Python 3 со стандартной библиотекой, а также git, diff и patch:

```bash
python3 tools/docs-lint.py
```

Проверяются:

- шапка в каждом файле документации и инструкций, включая скиллы проекта
- относительные ссылки и якоря
- наличие каждого файла в [карте источников истины](../README.md#карта-источников-истины)
- ссылка на реестр отложенных решений там, где есть неопределенные темы
- запрещенные символы типографики
- формат версии и дат конституции
- переопределение шаблона задач, в котором тесты обязательны
- настройки плагинов проекта
- наличие каждого файла харнеса на [схеме связей](../README.md#схема-связей) и в этом руководстве
- метка актуальности в шапке не старше минорной версии конституции
- цепочки подключения: импорт `AGENTS.md` в `CLAUDE.md`, скрипты хуков, команды хуков Spec Kit и скиллы, имена скиллов, строка `.omc/` в `.gitignore`
- существование принципов, на которые ссылаются тексты, и путей, упомянутых в документации
- совпадение переопределений шаблонов с ядром Spec Kit и с их патчами
- версия конституции в планах фич, когда они появятся

Режимы запуска: `--staged` для git-хука, `--hook` для хука после правки, `--session` для хука старта сессии, `--stamp <файл>` для метки актуальности, `--update-patches` и `--rebuild-overrides` для переопределений шаблонов. Нужны также утилиты `diff` и `patch`.

Запуск в CI сознательно отложен, см. [реестр отложенных решений](../decisions/README.md#отложенные-решения). Пока единственная защита это git-хук и хук старта сессии, поэтому согласованность `main` держится на дисциплине, а не на гарантии.

Режим `--staged` запускает git-хук. Он дополнительно проверяет по индексу, что версия конституции стала больше прежней и что в ней нет временного отчета о синхронизации. Остальные проверки читают рабочее дерево.

## Автоматизация AI-среды

| Механизм | Где настроен | Что делает |
|---|---|---|
| настройки Claude Code | `.claude/settings.json` | отключает перечисленные в файле плагины, запрещает чтение `.env` инструментом Read, force push и `--no-verify`, требует подтверждения правки конституции. Новый установленный плагин нужно добавить в список |
| хук после правки | `.claude/settings.json`, `tools/docs-lint.py` | проверяет документацию после правки файла с расширением md или файла настроек Claude Code, замечания показывает только по правленому файлу |
| хук перед командой | `.claude/settings.json`, `tools/guard-constitution.py` | требует подтверждения, если команда похожа на запись в конституцию. Это эвристика по тексту команды, а не гарантия |
| хуки Spec Kit | `.specify/extensions.yml` | после `/speckit-implement` и `/speckit-constitution` запускают `/docs-sync`, после поправки конституции дополнительно предлагают `/audit` |
| скилл `docs-sync` | `.claude/skills/docs-sync/SKILL.md` | сверяет изменившиеся факты с файлами-владельцами и запускает проверку |
| git-хук | `.githooks/pre-commit` | запускает проверку перед коммитом |
| переопределения шаблонов Spec Kit | `.specify/templates/overrides/tasks-template.md`, `.specify/templates/overrides/tasks-template.patch`, `.specify/templates/overrides/plan-template.md`, `.specify/templates/overrides/plan-template.patch` | шаблон задач делает тесты обязательными и первыми, как требует принцип VI, шаблон плана записывает версию конституции. Патч фиксирует отличие от ядра, проверка ловит расхождение после обновления Spec Kit |
| проверка при старте сессии | `.claude/settings.json`, `tools/docs-lint.py` с флагом `--session` | включает git-хук, если он выключен, и показывает агенту нарушения согласованности |
| метки актуальности | шапка каждого файла, `tools/docs-lint.py` с флагом `--stamp` | файл со старой минорной версией конституции считается устаревшим, пока его не сверят и не поставят метку |
| скилл `audit` | `.claude/skills/audit/SKILL.md` | отдельный агент ищет противоречия между конституцией и файлами харнеса, хук Spec Kit предлагает его после поправки конституции |
| напоминания о записи знаний | `.claude/settings.json`, `tools/capture-reminder.py` | хук Stop раз в 12 ходов просит агента проверить незаписанные решения. Хук PreCompact всегда помечает сессию, хук SessionEnd помечает ее, если было не меньше шести ходов. Оба ничего не передают модели, хук SessionStart напоминает о пометке в следующей сессии |
| скилл `capture` | `.claude/skills/capture/SKILL.md` | записывает решение из чата владельцу после подтверждения |
| скилл `harvest` | `.claude/skills/harvest/SKILL.md`, `tools/harvest.py` | ищет повторяющийся контекст в расшифровках сессий и в памяти Claude |
| скилл `cold-start` | `.claude/skills/cold-start/SKILL.md` | проверка с чистого листа по контрольным вопросам и замер размера контекста |

Заметки к таблице:

- Формат расшифровок сессий внутренний и может измениться. Если `tools/harvest.py` перестал находить реплики, он предупреждает об этом.
- Состояние напоминаний лежит вне репозитория: `~/.claude/projects/<проект>/capture/`. Частота напоминания хука Stop задается переменной окружения `CAPTURE_REMIND_EVERY`.
- Снять напоминание о неразобранных сессиях можно командой `python3 tools/capture-reminder.py clear`.
