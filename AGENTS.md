# AGENTS.md

> **Отвечает за:** общие инструкции для ИИ-агентов: что читать, как работать с репозиторием, как выполнять задачу, куда записывать решения.
> **Не содержит:** принципов и стека ([конституция](.specify/memory/constitution.md)), критериев проверки кода ([code-review.md](code-review.md)), настроек конкретного агента (для Claude Code это [CLAUDE.md](CLAUDE.md)).
> **Читать когда:** начинаете любую работу в репозитории.
> **Проверено при версии конституции:** 2.4.0

**TL;DR:** прочитай конституцию, найди владельца нужного факта по карте, работай от спецификации и не придумывай содержимое для отложенных тем.

## Что читать

- всегда: [конституция](.specify/memory/constitution.md)
- где живет нужный факт: [карта источников истины](docs/README.md#карта-источников-истины)
- работа над харнесом и вопросы о его устройстве: [docs/harness](docs/harness/README.md)
- работа над фичей: `spec.md`, `plan.md`, `tasks.md` и `research.md` в `specs/<NNN-feature>/`, создаются Spec Kit
- проверка и завершение работы: [code-review.md](code-review.md)
- тема кажется нерешенной: [реестр отложенных решений](docs/decisions/README.md#отложенные-решения)

## Правила работы с репозиторием

- Работа начинается со спецификации. Нет утвержденной спецификации - предложи `/speckit-specify` и не пиши код (принцип I). Исключения задает раздел "Переходный режим" конституции.
- Принцип IX обязателен: ищи владельца факта по карте, меняй факт только в его файле, используй только разрешенные AI-зависимости. Нашел дубль - сообщи, не поддерживай обе копии.
- Если задача упирается в тему из реестра отложенных решений, остановись и сообщи об этом, содержимое не придумывай.
- Язык текстов и кода задан в разделе процесса конституции, следуй ему.
- Конституцию не правь напрямую. Поправки идут только через `/speckit-constitution` и с подтверждением пользователя.

## Разграничение процесса

- Spec Kit ведет жизненный цикл фичи и владеет артефактами в `specs/<NNN-feature>/`. Статус задач ведется только в `tasks.md`.
- Исполнение отдельной задачи (исследование, тесты, реализация, проверка) - зона агента. Инструменты оркестрации исполнения подчиняются Spec Kit и не заводят собственных планов и списков задач для работы по фиче.
- Результаты исследований записываются в `research.md` фичи, а не в рабочее состояние оркестратора.
- Автономные режимы, где агент идет по шагам без человека, запускаются только на утвержденные задачи из `tasks.md`, не на идею и не на задачи, затрагивающие [горячие зоны](docs/architecture/hot-zones.md).
- Параллельно выполняются только задачи с пометкой `[P]` в `tasks.md`.
- `/speckit-analyze` и `/speckit-checklist` проверяют артефакты (спецификацию, план, задачи) до реализации. Код после реализации проверяется по [code-review.md](code-review.md). Эти проверки не заменяют друг друга.

## Выполнение задачи

1. Взять следующую невыполненную задачу из `tasks.md`.
2. Если нужно исследование, провести его и записать в `research.md`.
3. Написать тест и убедиться, что он падает по правильной причине (принцип VI конституции).
4. Реализовать минимально.
5. Проверить завершение по [разделу процесса конституции](.specify/memory/constitution.md#процесс-разработки-и-контроль-качества) и по [code-review.md](code-review.md).
6. Обновить файлы-владельцы изменившихся фактов, запустить [проверку документации](docs/harness/reference.md#проверка-документации), а если менялся харнес, еще и [тесты харнеса](docs/harness/reference.md#тесты-харнеса), затем отметить задачу.

## Фиксация решений и повторяющихся действий

Решение из обсуждения записывается в той же задаче, что и изменение, по таблице:

| Что решено | Куда записать |
|---|---|
| поведение фичи, ответы на уточнения | `spec.md` фичи |
| исследование, выбор варианта внутри фичи | `research.md` фичи |
| принцип, стек, обязательное правило | поправка конституции |
| процесс AI-среды, документация | файл-владелец по карте |
| тема отложена | строка в [реестре](docs/decisions/README.md#отложенные-решения) |
| архитектурное решение с причинами | ADR в [docs/decisions](docs/decisions/README.md#формат-adr) |

Правила:

- Журнал переписки не ведется, решения записываются по таблице выше.
- Что должно пережить сессию, записывай командой `/capture`: без записи сказанное в чате пропадет.
- Спорные вопросы по фиче решай через `/speckit-clarify`, чтобы ответы остались в `spec.md`.
- Предлагай пользователю запускать `/harvest` для поиска повторяющегося контекста и `/cold-start` для проверки с чистого листа.
- Заметил повторяющееся действие - предложи пользователю оформить его скиллом. Оформляй в `.claude/skills/<имя>/SKILL.md` только после согласия.
- Механизмы автообновления и проверки описаны в [справочнике харнеса](docs/harness/reference.md#автоматизация-ai-среды).
