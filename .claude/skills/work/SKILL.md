# work

> **Отвечает за:** порядок работы с трекером `work/` в разговоре: доска, очередь, создание простых элементов, смена статуса.
> **Не содержит:** формата элементов и команд трекера ([справочник харнеса](../../../docs/harness/reference.md#трекер-работы)), создания эпика ([epic-new](../epic-new/SKILL.md)) и передачи фичи в Spec Kit ([work-start](../work-start/SKILL.md)).
> **Читать когда:** пользователь спрашивает, что делать дальше, как идет работа, или просит завести задачу, баг или исследование.
> **Проверено при версии конституции:** 3.0.0

## Шаги

1. Вопрос "как идет работа": выполни `python3 tools/work.py board` и перескажи прогресс эпиков.
2. Вопрос "что дальше": выполни `python3 tools/work.py next` и предложи элемент. Для фичи предложи `/work-start`. Независимые элементы можно вести параллельно только с оговоркой, что места частых конфликтов правок решает владелец.
3. Просьба завести элемент (задача, баг, инцидент, исследование, харнес): выясни название, тип и приоритет, покажи команду `python3 tools/work.py new` и выполни ее после подтверждения. Для эпика предложи `/epic-new`, для фичи тоже `/epic-new` или `new` с `--parent` по решению владельца.
4. Смена статуса: только по прямой команде владельца в разговоре, командой `python3 tools/work.py set <номер> --status <статус>`. Перевод "идея" в "готово к работе" агент сам не делает.
5. После изменений запусти `python3 tools/work.py check`.

## Границы

- Не создавай спецификации и не запускай Spec Kit.
- Не меняй статус без прямой команды владельца.
- Статус фичи со spec и статус эпика выводятся из артефактов, вручную их не правь.
- Не делай коммит.
