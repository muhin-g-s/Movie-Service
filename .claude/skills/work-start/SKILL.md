# work-start

> **Отвечает за:** порядок передачи одной фичи из трекера `work/` в цикл Spec Kit.
> **Не содержит:** самого цикла Spec Kit (скиллы `speckit-*`), формата элементов и команд трекера ([справочник харнеса](../../../docs/harness/reference.md#трекер-работы)) и создания эпика ([epic-new](../epic-new/SKILL.md)).
> **Читать когда:** пользователь вызвал `/work-start` или хочет взять следующую фичу в работу.
> **Проверено при версии конституции:** 3.0.0

Передается строго одна фича за раз: спецификации, созданные заранее, устаревают, а нумерация Spec Kit последовательная.

## Шаги

1. Определи элемент: номер из аргумента команды или выбор владельца из списка `python3 tools/work.py next`. Если список пуст, сообщи, чего не хватает (статус, зависимости), и остановись.
2. Проверь элемент командой `python3 tools/work.py show <номер>`: тип фича, статус "готово к работе", зависимости выполнены, своей спецификации еще нет. Нарушение любого условия означает отказ с объяснением. Статус "идея" не повышай сам, его меняет только владелец.
3. Подготовь вхождение для `/speckit-specify`: название и описание элемента, цель эпика как контекст, ссылки на спецификации выполненных зависимостей, критерии на уровне пользователя. Решений по реализации во вхождении быть не должно (принцип I). Покажи вхождение владельцу.
4. Учти вид элемента. Для исследовательской и фундаментной фичи уровень контроля не ниже контрольной точки, а вариант решения перед планом ДОЛЖЕН быть записан в `research.md` и утвержден владельцем.
5. Запусти `/speckit-specify` с этим вхождением. Spec Kit создаст каталог в `specs/`.
6. Привяжи результат: `python3 tools/work.py link <номер> specs/<каталог>`. Перенеси уровень контроля элемента в поле Control level файла `spec.md`.
7. Запусти `python3 tools/work.py check`, исправь замечания.
8. Остановись на утверждении спецификации. Предложи следующие шаги: `/speckit-clarify` при открытых вопросах, затем `/speckit-plan` (хук спросит о горячих зонах), а шаги без диалога можно отдать цепочке `feature-chain`.

## Границы

- Не бери в работу несколько фич сразу.
- Не запускай план, задачи и реализацию сам: это решение владельца после утверждения спецификации.
- Не меняй статус элемента вручную: после привязки он выводится из каталога фичи.
- Не делай коммит.
