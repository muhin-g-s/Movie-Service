# docs-sync

> **Отвечает за:** порядок синхронизации документации с изменениями: сверка фактов с владельцами, обновление меток и запуск проверки.
> **Не содержит:** самих правил документации ([принцип IX конституции](../../../.specify/memory/constitution.md)) и карты владельцев ([docs/README.md](../../../docs/README.md#карта-источников-истины)).
> **Читать когда:** срабатывает хук Spec Kit или нужно сверить документацию после изменений.
> **Проверено при версии конституции:** 2.4.0

## Шаги

1. Определи изменения: `git status --short` и `git diff`. Для фичи учти также `specs/<NNN-feature>/`.
2. Для каждого изменившегося факта найди владельца в карте источников истины и обнови его. Остальные места должны только ссылаться, копий быть не должно.
3. Запусти `python3 tools/docs-lint.py` и прочитай замечания.
4. Если изменилась конституция, проверь, что версия повышена. Для каждого файла с устаревшей меткой прочитай его целиком, сверь с новой редакцией, поправь и поставь метку: `python3 tools/docs-lint.py --stamp <файл>`. Метку нельзя ставить без сверки. Для смысловой проверки предложи пользователю `/audit`.
5. Если проверка сообщает, что переопределение шаблона расходится с ядром Spec Kit, после обновления Spec Kit выполни `python3 tools/docs-lint.py --rebuild-overrides`, затем проверь результат. Если файл был изменен осознанно, выполни `--update-patches`.
6. Если решена тема из реестра отложенных решений, удали строку из [реестра](../../../docs/decisions/README.md#отложенные-решения) и запиши решение в файл-владелец. Если появилась новая отложенная тема, добавь строку в реестр.
7. Повтори проверку и исправь все замечания.
8. Сообщи пользователю: что обновлено, что осталось не определено.

## Границы

- Не делай коммит.
- Не правь конституцию сам: поправки идут через `/speckit-constitution` с подтверждением пользователя.
- Не придумывай содержимое для отложенных тем.
