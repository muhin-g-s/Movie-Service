# audit

> **Отвечает за:** порядок смыслового аудита: поиск противоречий между конституцией и файлами харнеса.
> **Не содержит:** самих правил (они в [конституции](../../../.specify/memory/constitution.md)) и механических проверок (их делает `tools/docs-lint.py`).
> **Читать когда:** пользователь вызвал `/audit`, после поправки конституции или перед пилотной фичей.
> **Проверено при версии конституции:** 3.0.0

Механическая проверка ловит форму и связи. Противоречия по смыслу может найти только модель, поэтому аудит делает отдельный агент со свежим контекстом.

## Шаги

1. Составь список файлов харнеса: файлы из [карты источников истины](../../../docs/README.md#карта-источников-истины), `AGENTS.md`, `CLAUDE.md`, `code-review.md`, скиллы проекта.
2. Запусти одного агента через инструмент Agent, тип Explore. Передай конституцию как эталон и список файлов. Попроси найти: противоречия по смыслу, одно правило в двух местах (нарушение принципа IX), ссылки на несуществующее, утверждения, которых нет в эталоне, выдуманное содержимое для отложенных тем. Каждое замечание: файл, строка, цитата, почему проблема.
3. Проверь каждое замечание сам по файлу, ложные отбрось.
4. Покажи пользователю подтвержденные замечания и предложенные правки. Применяй после подтверждения.
5. Запусти `python3 tools/docs-lint.py`. Для файлов, которые ты сверил с конституцией, поставь метку: `python3 tools/docs-lint.py --stamp <файлы>`.
6. Сообщи пользователю, что найдено, что исправлено и что осталось.

## Границы

- Не правь конституцию, поправки идут через `/speckit-constitution`.
- Не ставь метку на файл, который не сверен.
- Не делай коммит.
