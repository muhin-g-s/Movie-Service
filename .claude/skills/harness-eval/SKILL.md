# harness-eval

> **Отвечает за:** порядок прогона сценариев поведения агента и разбора провалов.
> **Не содержит:** самих сценариев (они в `evals/cases/`), логики запуска (ее выполняет `tools/harness-eval.py`) и правил харнеса.
> **Читать когда:** пользователь вызвал `/harness-eval`, после правки харнеса, смены модели или версии Claude Code.
> **Проверено при версии конституции:** 3.0.0

Сценарии запускают Claude Code без интерфейса во временной копии репозитория. Настоящие файлы они не меняют, но тратят токены.

## Шаги

1. Уточни у пользователя, что запускать. По умолчанию все быстрые сценарии, модели `sonnet,haiku`, по три запуска на каждую. Медленные сценарии добавляются флагом `--slow`, вопросы `cold-start` набором `--suite cold-start`.
2. Запусти `python3 tools/harness-eval.py` с выбранными параметрами. Первая модель в списке рабочая и определяет код возврата.
3. Прочитай таблицу и разбери по правилу: прошла рабочая и слабая, харнес надежен. Прошла рабочая, провалила слабая, харнес держится на силе модели, предложи прояснить формулировки. Провалила рабочая, это дефект харнеса или сценария.
4. Для каждого дефекта сначала проверь, что провал настоящий: посмотри пояснение проверки и при необходимости повтори сценарий.
5. Если дефект настоящий, исправь харнес в файле-владельце и повтори сценарий. Если сценарий проверяет не то, исправь сценарий.
6. Новая ошибка харнеса, найденная вне прогона, сначала становится сценарием в `evals/cases/`, потом исправляется.
7. Запусти `python3 tools/docs-lint.py` и `python3 -m unittest discover -s tests/harness`.
8. Сообщи пользователю таблицу, найденные дефекты, что исправлено и стоимость прогона.

## Границы

- Не делай коммит.
- Не запускай медленные сценарии и большие наборы без согласия пользователя.
- Не правь конституцию, поправки идут через `/speckit-constitution`.
