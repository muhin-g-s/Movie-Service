# epic-new

> **Отвечает за:** порядок диалога, в котором из цели владельца получается эпик и список его фич в трекере `work/`.
> **Не содержит:** формата элементов и команд трекера ([справочник харнеса](../../../docs/harness/reference.md#трекер-работы)), критериев хорошей задачи ([реестр отложенных решений](../../../docs/decisions/README.md#отложенные-решения)) и передачи фичи в Spec Kit ([work-start](../work-start/SKILL.md)).
> **Читать когда:** пользователь вызвал `/epic-new` или хочет разбить большую цель на фичи.
> **Проверено при версии конституции:** 3.0.0

Содержимое эпика принадлежит владельцу. Агент предлагает структуру, но цель, границы и критерии не придумывает.

## Шаги

1. Прочитай существующие элементы: `python3 tools/work.py board`. Не дублируй уже заведенное.
2. Прочитай [реестр отложенных решений](../../../docs/decisions/README.md#отложенные-решения) и ограничения конституции: темы из реестра нельзя решать за владельца.
3. Задай владельцу вопросы по очереди: цель эпика, что явно вне границ, критерии готовности, которые можно наблюдать. Если владелец не отвечает на пункт, запиши "не определено", не заполняй его догадкой.
4. Предложи декомпозицию на фичи. Каждая фича это вертикальный срез, который проверяется отдельным тестом. Для каждой укажи название, вид (простой, исследовательский, фундамент), зависимости между фичами, приоритет P1-P3 и уровень контроля по умолчанию из [bricks.md](../../../docs/harness/bricks.md#уровни-контроля). Исследовательскую и фундаментную фичу нельзя ставить на автономный уровень. Темы, отложенные в реестре, оформляй отдельными исследовательскими элементами впереди зависимых фич.
5. Покажи список владельцу, внеси его правки и получи явное подтверждение.
6. Только после подтверждения создай элементы командой `python3 tools/work.py new` (сначала эпик, затем фичи с `--parent` и `--depends`), заполни разделы элементов ответами владельца через `--body`.
7. Запусти `python3 tools/work.py check`, исправь замечания, покажи `python3 tools/work.py board`.
8. Скажи владельцу, что новые фичи имеют статус "идея", а в "готово к работе" их переводит только он.

## Границы

- Ничего не записывай до подтверждения списка.
- Не создавай спецификации и каталоги в `specs/`, передачу в Spec Kit делает `work-start`.
- Не переводи элементы в "готово к работе" сам.
- Не придумывай содержимое для отложенных тем.
- Не делай коммит.
